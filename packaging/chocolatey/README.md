# Chocolatey package `instafind`

- `instafind.nuspec` and `tools/chocolateyinstall.ps1` are generated by
  `packaging/update-manifests.py` (version, URL, SHA-256). Edit the templates in
  that script, not these two files.
- `tools/chocolateyuninstall.ps1` and `tools/chocolateybeforemodify.ps1` are
  hand-written and do not change between releases.

At install time the package downloads `bahth.exe` from the GitHub release,
checks its SHA-256, shims it as `bahth` (automatic), and adds a
Start menu shortcut. `beforemodify` closes a running copy before upgrade and
uninstall. Uninstall also removes the "Start with Windows" entry when it
points at the package. User data in `%LOCALAPPDATA%\BahthSari` stays.

## Pushing a version

You need an account on https://community.chocolatey.org and its API key
(Account → API Keys). Then, on Windows with Chocolatey installed:

```powershell
choco apikey add --source https://push.chocolatey.org/ --key <API-KEY>   # once
choco pack packaging\chocolatey\instafind.nuspec --outputdirectory out
choco install instafind --source .\out -y        # test locally, as admin
choco uninstall instafind -y
choco push out\instafind.<version>.nupkg --source https://push.chocolatey.org/
```

Or let CI do it: add the key as the repository secret `CHOCOLATEY_API_KEY`
and `.github/workflows/packaging.yml` packs and pushes each release (build.yml
starts that workflow after publishing a release).

Every pushed version goes through Chocolatey's automatic validator and
verifier (a test install). The first versions also wait for a human moderator,
which can take days or weeks. The package appears publicly only after approval.
Before the first push, set `<owners>` in the template (in
`update-manifests.py`) to your chocolatey.org user name.
